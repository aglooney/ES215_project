# Brazilian Grid Modeling Toolkit

This project builds an integrated data+model pipeline to analyze Brazil’s electric grid using publicly available generation, weather, and demand data. The end-to-end workflow:

1. Downloads and cleans plant-level generation data (ONS), weather reanalysis, and subsystem demand projections.
2. Aligns generation units with nearby weather grid cells and exports a unified CSV (`data/merged_generation_weather.csv`).
3. Converts monthly demand projections into subsystem-level MW loads.
4. Builds and runs a Pandapower-based DC optimal power flow (OPF) that:
   - Uses actual monthly average generation per subsystem,
   - Adds “proxy” conventional generators to represent plants missing from the weather-linked dataset,
   - Supports stochastic perturbations of generation to study uncertainty,
   - Outputs curtailment/balancing results.
5. Provides helper scripts for generation-vs-demand comparisons and batch uncertainty studies.

This README documents the data sources, key scripts, usage examples, and assumptions.

## 2. Preprocessing Pipeline

All preprocessing scripts live in `csv_preprocessing/`. Run them in the order below (adjusting file paths to your storage).

1. **Generation metadata**  
   - `gen_data_format.py`: Renames ONS CSV columns and ensures consistent date formats.  
   - `adjust_id_format.py`: Harmonizes plant `ceg` IDs between datasets.  
   - `match_ids.py`: Merges generator CSVs with coordinate files.  
   - `adjust_lat_long.py`: Cleans up coordinate precision and units.

2. **Weather processing**  
   - `gen_weather_data.py`: Extracts the desired variables from netCDF files and concatenates them into a single CSV.  
   - `nc_to_csv.py` / `view_nc_file.py`: helpers for inspecting netCDF files if needed.

3. **Generation + Weather merge**  
   - `combine_gen_weather.py`:  
     1. Reads cleaned generation + weather CSVs.  
     2. Aggregates plant output to daily MWh, keeping static attributes such as `subsys_id`, `subsys_name`, `state_id`, etc.  
     3. Matches each plant to the nearest weather cell using `scipy.spatial.cKDTree`.  
     4. Writes `data/merged_generation_weather.csv`, which is the primary modeling dataset.

4. **Demand formatting**  
   - `convert_demand_format.py`:  
     - Flattens the multi-row Excel headers,  
     - Cleans decimal/thousand separators,  
     - Melts the table to `[state, subsystem, year, month, MWh]`,  
     - Saves to `data/demand_data/demand_projection_clean.csv` (and optional parquet).

## 3. Core Analysis Scripts

### 3.1 `compare_gen_demand.py`

Purpose: Quick comparison of subsystem demand vs generation over a date range.

Workflow:
1. Loads `data/demand_data/demand_projection_clean.csv`, filters to `--start-date` → `--end-date`, and converts monthly MWh to average MW (with optional `--demand-scaling` multiplier).
2. Loads `data/merged_generation_weather.csv`, filters by date, sums daily MWh per subsystem, and converts to average MW over the same window.
3. Merges both tables and prints the demand, generation, and surplus/deficit per subsystem (Paraguai rows can be dropped via `--exclude-paraguai`).

Usage example:
```
python compare_gen_demand.py --start-date 2020-01-01 --end-date 2020-02-01 --demand-scaling 1.0
```

Outputs a table and (optionally) `--output path.csv`.

### 3.2 `generation_demand_gap.py`

Purpose: Month-by-month and annual summaries of generation vs demand gaps, with totals.

- Reads the same demand and generation files, converts to MW, and produces:
  - Monthly table with `demand_avg_mw`, `gen_avg_mw`, and both average and scaled gaps.
  - Totals row per month (sum of all subsystems).
  - Annual averages for each subsystem and the total.
- `--exclude-paraguai` toggles whether the Itaipu import is considered.
- `--output monthly.csv` writes the monthly table; an annual CSV is automatically saved as `monthly.annual.csv`.

Example:
```
python generation_demand_gap.py --start 2020-01 --end 2020-12 --demand-scaling 1.0 --output results/monthly.csv
```

### 3.3 `run_curtailment_opf.py`

The main DC-OPF workflow. Major steps:

1. **Arguments** (`python run_curtailment_opf.py --help`):
   - `--year`, `--month`: target month (defaults 2020-12).
   - `--demand-scaling`: multiplier for monthly average load (default 1.3).
   - `--generation-path`: default `data/merged_generation_weather.csv`.
   - `--gen-scale-mean`, `--gen-scale-std`, `--seed`: specify stochastic scaling of generation (mean and standard deviation for a normal draw applied independently per subsystem). Set std>0 to enable uncertainty runs.
   - `--results-path`: output CSV for curtailment results.

2. **Demand conversion**  
   Reads the cleaned demand CSV, filters to `(year, month)`, and converts monthly MWh to average MW → peak MW using `DEMAND_SCALING`.

3. **Generation aggregation**  
   Aggregates the merged generation CSV to the same month and converts to average MW per subsystem (including PARAGUAI). Applies optional stochastic scaling factors.

4. **Proxy generators**  
   For each domestic subsystem, computes `proxy = max(demand_peak − gen_avg, 0)`. Adds `GEN_CONV_<SUBSYS>` sgens at the subsystem hub buses with `max_p_mw = proxy` and higher marginal cost (`PROXY_COST`, default 50) so they dispatch only when renewables can’t cover load.

5. **Network load/injection**  
   Loads the Pandapower JSON network, attaches subsystem loads to their hub buses, and sets renewable sgen limits to the aggregated monthly averages. PARAGUAI remains as the Itaipu import bus.

6. **DC OPF**  
   Runs `pp.rundcopp` (DC optimal power flow). The script ensures `sgen`/`load` elements have the required columns (`controllable`, `min_q_mvar`, `max_q_mvar`).

7. **Output**  
   Writes per-generator curtailment (pmax − dispatch) to the specified results CSV. Renewable sgens currently appear with placeholder dispatch because they sit at single aggregated buses; proxy units show actual dispatch.

Example:
```
source es215_env/bin/activate
python run_curtailment_opf.py --year 2020 --month 12 --demand-scaling 1.1 --gen-scale-std 0.05 --seed 42 --results-path results/curtailment_2020_12.csv
```

### 3.4 `run_uncertainty_batch.py`

Thin wrapper to run `run_curtailment_opf.py` multiple times with different random seeds to analyze the effect of generation uncertainty.

Arguments:
- `--python`: interpreter (`python`, `es215_env/bin/python`, etc.).
- `--runs`: number of samples.
- `--std`: standard deviation passed to `run_curtailment_opf.py --gen-scale-std`.
- `--start-seed`: starting seed; each run increments by 1.
- `--results-dir`: where per-run CSVs and the aggregated file are stored.
- `--extra-args --year 2021 --month 6 ...`: any additional OPF CLI args appended verbatim after `--extra-args`.

Example:
```
source es215_env/bin/activate
python run_uncertainty_batch.py --python python --runs 10 --std 0.05 \
    --results-dir results/uncertainty_2020_12 \
    --extra-args --year 2020 --month 12 --demand-scaling 1.2
```

Outputs:
- `results/uncertainty_2020_12/curtailment_seed_<n>.csv` for each run.
- `results/uncertainty_2020_12/curtailment_uncertainty.csv` aggregated across seeds (with an added `seed` column).

## 4. Supporting Scripts/Notebooks

- `build_network_with_generators.py`: Assembles the Pandapower network from buses, lines, and subsystem generator data. Use it when the topology or generator placements change.
- `generate_scenario.py`: Legacy script that aggregated generation for a single date and wrote a parquet scenario. The new `run_curtailment_opf.py` performs aggregation on the fly; keep this script for reproducibility or if you need static scenario files.
- `basic_ml_model.py`, `eda.ipynb`: Exploratory modeling of plant-level generation using weather features. Generates ML forecasts (not yet integrated into the OPF automatically but can supply alternative generation columns).
- `results/curtailment_results.csv`: Latest OPF output from `run_curtailment_opf.py`.
- `models/baseline_outputs/`: Stores comparisons between baseline and ML forecasts—useful for quantifying forecast error distributions before feeding them into the OPF’s stochastic scaling.

## 5. Assumptions & Notes

1. **Units**  
   - Demand in `demand_projection_clean.csv` is monthly MWh; scripts convert to MW by dividing by hours (and multiply by `DEMAND_SCALING` to approximate peak-hour load).  
   - `gen_val(MW)` in `data/merged_generation_weather.csv` represents daily energy (MWh). Every script divides by 24×days to convert to MW.

2. **Paraguai / Itaipu**  
   - PARAGUAI is treated as an import-only subsystem supplying Brazil; we keep it in the generation aggregation so totals match real consumption. Demand scripts exclude it since there’s no Brazilian load there.

3. **Proxy generators**  
   - Represent the conventional fleet (thermal + large hydro) not included in the weather-linked dataset. Their MW capacities are calculated per month per subsystem as the residual between peak demand and renewable (plus import) averages.  
   - Cost settings (`PROXY_COST`) ensure renewables dispatch first, then proxies, then the slack/ext grid.

4. **Stochastic scaling**  
   - The OPF can perturb each subsystem’s renewable generation with independent normal draws (mean=1, std specified). This is a simple way to propagate forecast uncertainty; for correlated uncertainty, extend the scaling logic to use correlated samples.

5. **Environment**  
   - All examples assume the `es215_env` virtual environment is active: `source es215_env/bin/activate`. Ensure `pandapower`, `numpy`, `pandas`, `scipy`, etc. are installed there.  
   - Matplotlib warnings arise from read-only home directories; set `MPLCONFIGDIR` if needed, but they don’t affect OPF runs.

6. **Extensibility**  
   - To use ML forecasts instead of monthly averages, extend `run_curtailment_opf.py` to load predicted generation values (per subsystem) and replace `subsys_gen` with those predictions before running the OPF.  
   - To model curtailment at finer granularity, add more buses/generators (e.g., per-state or per-plant) to the Pandapower network and re-run `build_network_with_generators.py`.

## 6. Typical Workflow Summary

1. **Prepare data**  
   ```
   python csv_preprocessing/combine_gen_weather.py
   python convert_demand_format.py
   ```
2. **Quick sanity check**  
   ```
   python compare_gen_demand.py --start-date 2020-01-01 --end-date 2020-12-31
   ```
3. **Run a single OPF**  
   ```
   source es215_env/bin/activate
   python run_curtailment_opf.py --year 2020 --month 12 --demand-scaling 1.2 --results-path results/curtailment_2020_12.csv
   ```
4. **Batch uncertainty study**  
   ```
   python run_uncertainty_batch.py --runs 20 --std 0.08 --results-dir results/uncertainty_2020_12 --extra-args --year 2020 --month 12 --demand-scaling 1.2
   ```
5. **Analyze gaps or trends**  
   ```
   python generation_demand_gap.py --start 2020-01 --end 2022-12 --output results/monthly.csv
   ```

With this toolkit you can quantify subsystem imbalances, explore the reliance on imports/proxy generation, and propagate renewable forecast uncertainty through the Brazilian grid model.
